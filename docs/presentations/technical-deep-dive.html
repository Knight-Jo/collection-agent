CTO：90 秒理解系统

这不是一个“模型直接上网然后写答案”的聊天应用，而是一套将搜索、材料、证据、结论和报告分层治理的本地调研系统。

解决什么问题

围绕一个主题持续开展公开信息调研，把分散网页和多媒体材料转化为可引用、可复核的结构化报告。

核心技术壁垒

递归与动态网页采集、多媒体解析、证据精确定位、独立审核、冲突与覆盖治理共同形成证据链。

为什么本地部署

模型、任务状态、原始材料和报告留在本机；支持 OpenAI 兼容模型接口，便于按资源和安全要求替换模型。

当前工程边界

单机单用户、双路推理、SQLite WAL 和文件系统；不引入 Redis、Celery 与多用户权限，保持首版简单可运维。

关键决策：Conversation 负责交互，Research Runtime 负责执行，Committed State 才能作为事实依据，ReportVersion 固化阶段性产物。四者不混用，系统才能安全续研、恢复和审计。

新成员：从用户问题到报告

先理解六个对象和两条路径，再进入代码。不要一开始就钻进两千行的 StateStore 或 Agent 工具集合。

Conversation用户交流上下文；可以归档恢复，不拥有研究资产。
IntelTask一个长期调研主题，冻结目标、问题和范围。
ResearchRun一次明确授权的研究执行；失败重试会创建新 Run。
IntelDocument抓取并校验后的原始材料及解析文本。
Fact / Evidence原子事实及其精确引文、位置和支持关系。
ReportVersion绑定特定研究状态的不可覆盖报告版本。

路径 A：询问已有材料

用户提问

ConversationRuntime 接收消息，DialogueEngine 识别为 QUERY。

检索证据

TaskRetriever 只从当前 Task 的 committed 材料、Fact 和 Evidence 中召回相关段落。

生成回答

DialogueEngine 形成 AnswerResult；服务端把 Citation 绑定到稳定的文档与位置，SSE 流式展示。

路径 B：明确要求继续调研

创建动作

DialogueEngine 识别 CONTINUE / MODIFY / CONTROL，生成 ActionRequest，而不是直接偷偷搜索。

执行研究

ContinuationRunner 启动 ResearchRun，Agent 规划、搜索、抓取、解析并治理事实证据。

提交产物

ResearchCheckpoint 把新增资产原子提交到 committed state；报告仍需用户显式生成。

材料为什么不等于证据

搜索结果只是候选线索；IntelDocument是已归档材料；Evidence是材料中能够支撑或反驳一个 Fact 的精确片段；只有经过支持审核和覆盖评估的证据，才进入正式结论。

建议的 30 分钟阅读顺序

  1. CONTEXT.md：统一领域术语。
  2. src/intel_agent/web/app.py：看系统如何装配。
  3. conversation.py：看消息、动作和运行如何衔接。
  4. runner.py → agent.py：看 Agent 如何执行研究工具。
  5. state_db.py / storage.py：看状态与内容如何落盘。

开发者：代码模块地图

从“责任”找模块，不要从文件名猜调用关系。后端生产代码位于 src/intel_agent/，前端位于 web/src/，测试与模块基本同名。

能力层主要入口职责通常不要在这里做什么
应用装配web/app.py
main.py		加载配置，组装 FastAPI、LegacyRunAdapter、ConversationRuntime 和本地依赖状态。不要放搜索、证据或业务状态规则。
对话控制conversation.py
intake.py · dialogue.py		处理消息、Intake、意图、ActionRequest、流式事件和用户控制。Dialogue 不直接搜索，也不直接修改 Evidence。
研究编排runner.py
agent.py · continuation.py		构造任务提示、Agent 工具集、运行预算、续研范围和 checkpoint 提交。不要让一次失败执行原地复活；重试必须是新 Run。
搜索发现search/
search/provider.py · search_queries.py		通用搜索、垂直 Provider、查询矩阵、来源类型、限速、缓存与去重。搜索摘要不能直接成为 Evidence。
安全采集fetch.py · crawl.py
browser.py · security.py		URL 规范化、SSRF 防护、DNS pinning、robots、递归队列、浏览器渲染与归档。不要绕过逐跳重定向校验或把浏览器变成无限制网络代理。
内容解析extract.py
document_extract.py		HTML、PDF、Office、图片 OCR、音视频转写、链接发现和处理器降级。处理器不可用时不得伪造正文或证据。
证据治理fact.py · evidence.py
audit.py · conflicts.py · coverage.py		Fact、精确引文、支持审核、冲突、独立来源和问题覆盖。Fact/Evidence 内容不可原地改写；纠正应创建新对象并 supersede。
持久状态state_db.py · state_store.py
storage.py		SQLite schema、事务状态关系、持久事件，以及文件资产、哈希和安全路径。不要产生 SQLite/JSON 双写真相或绕过事务直接改表。
报告输出report.py
report_versions.py		从已验证结论生成报告文件，创建、读取、发布和失效 ReportVersion。不要自动覆盖 Published，不要引用未提交 working assets。
Web 交互web/conversation.py
ConversationWorkbenchPage.tsx · ConversationPanel.tsx		HTTP/SSE 契约、三栏工作台、时间线、状态卡和上下文详情。Timeline 是投影，前端不能把它当作领域真相源。

扩展功能：从哪里入手修改

每类扩展都从现有 seam 进入。先补一个最小失败测试，再修改实现；涉及公开行为时同步更新配置、接口或架构文档。

新增搜索来源

实现匿名 SearchProvider，声明准入元数据，加入 Provider 注册和相应配置；保持统一 SearchResult 与去重策略。

新增文件或媒体格式

关键领域关系

  • IntelTask 1:N ResearchRun：每轮续研都有独立运行轨迹。
  • IntelTask 1:N Conversation：会话可归档恢复，但不删除任务资产。
  • IntelDocument → Fact → Evidence：材料、事实和依据严格分层。
  • ReportVersion → Checkpoint：报告可还原生成时采用的事实世界。
