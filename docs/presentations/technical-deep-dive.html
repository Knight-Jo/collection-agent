DESIGN PRINCIPLES

五条原则，决定系统的确定性边界

P1

从答案导向转向证据导向

报告不是模型的自由发挥，而是对已验证事实的结构化组织。

P2

从 Query 驱动转向问题与缺口驱动

下一动作由「问题 × 来源角色 × 证据缺口」决定，而非反复换关键词。

P3

Search 与 Fetch 分离

搜索只产出候选；抓取归档正文后才进入证据链，杜绝“摘要当证据”。

P4

模型判断与确定性控制分离

模型负责理解、规划、选择；程序负责校验、限制、留痕。

P5

权威状态与派生视图分离

intel_state 是唯一真源；轨迹、报告、界面是它的投影，可重建、不漂移。

对应实现：agent.py（模型判断）、task.py / evidence.py / coverage.py / storage.py（确定性控制）。

05 / 14

AUTHORITATIVE DATA MODEL

权威对象与稳定追溯链

权威对象（intel_state）

  • IntelTask 任务、CrawlSnapshot 抓取队列、IntelDocument 归档文档
  • Fact 原子事实、EvidenceSupport 精确引文、SupportReview 审核裁决
  • EvidenceConflict 冲突、CoverageSnapshot 覆盖快照、报告产物绑定

稳定追溯链

  • 报告结论 → Fact ID → Evidence ID → 原文行号 → Document ID
  • 文档与正文均为内容寻址（SHA-256），ID 可复现，防篡改
  • 覆盖快照、报告、引用文档哈希绑定；任一变化拒绝错误完成
派生数据（报告文本、界面、轨迹）一律从权威对象重建，不作为独立事实来源。

模型定义：models.py；持久化：storage.py（原子写 + SHA-256 + 越界防护）。

06 / 14

SEARCH & EVIDENCE COVERAGE

把“搜得充分”变成可计算状态

问题 × 来源覆盖矩阵

每个问题跟踪覆盖状态（answered / partial / gap / conflicted）与缺口分数。

缺口驱动下一动作

由缺口（缺一手来源、未交叉验证、缺时效）决定下一次查询，而非模型“感觉充分”。

Candidate Ledger

候选来源统一记账，跨引擎去重、域名公平排序、归档状态跟踪。

Evidence Gain

停止搜索依赖边际证据收益；连续两轮 gap 不降即停止并诚实披露缺口。

信息空间发现

Sitemap、RSS、下载中心、IR 页面、实体关系，超越单一搜索引擎入口。

本地材料优先补证

已归档材料优先用于交叉验证，避免重复联网。

对应实现：coverage.py、search_queries.py、crawl.py；缺口驱动见 agent.py 的 _run_query_matrix。

OBSERVABILITY

三层可观测体系：同一条事件流，三个投影

技术运行层

机器实际执行了什么

model_call / action / observation：模型请求、工具调用、耗时与 Token，服务工程优化。

业务决策层

智能体为什么这样跑

decision + reason_codes + state_snapshot：决策、理由码、当时状态切片，服务调试与蒸馏。

结果评估层

这次跑得好不好

run_finished + coverage：覆盖分数、gap、报告完整性与成本。

统一 Envelope：run_id → step_id → event_id 串联三种投影；同一事件流落盘 trace.jsonl，不另起三套存储。

实现：trajectory.py（事件流 + 记录器）、reason_rules.py（理由码）、scripts/analyze_trajectory.py（重建因果链）、logging.py（分级日志）。

ACQUISITION & MULTIMEDIA

安全获取链 + 多媒体材料处理

安全获取链

  • 公网地址校验、DNS pinning、逐跳重定向检查（防 SSRF / rebinding）
  • robots.txt 遵守、域名限速、并发与字节预算、失败重试、缓存复用
  • 动态页面按需启用 Chromium，限制页时间/请求数/字节，沙箱失败即关闭

多媒体提取

  • PDF（文本优先、无文本转 OCR，限制页数与时间）
  • Office（DOC/XLS/PPT，旧格式经 LibreOffice）、图片 OCR（Pillow 校验 + Tesseract）
  • 音视频（FFmpeg + faster-whisper 转写，保留时间戳文本）
  • 处理器缺失时保留原件但标记 unavailable，禁止进入证据链

实现：fetch.py、security.py、crawl.py、browser.py、extract.py、document_extract.py。

EVIDENCE BY DESIGN

正式结论必须穿过四道门

01 / FACT

原子事实

复合陈述拆成可单独验证、可替换的事实单元。

02 / QUOTE

精确引文

逐字存在于归档正文，记录起止行号或时间戳。

03 / REVIEW

隔离审核

独立审核模型判定 full / partial / irrelevant / contradicts。

04 / COVERAGE

覆盖门控

按来源独立性、质量、时效与冲突判断可否入报告。

声明分级：primary 一手披露可由单一官方来源支持；corroborated 重大数字要求多独立来源组；reported 保留但标注转述；inference 必须绑定两个已验证事实。

实现：fact.py、evidence.py、audit.py、conflicts.py、coverage.py、storage.py。

状态替代长记忆

对话裁剪后，从任务、文档、事实、证据、审核、覆盖状态重建快照，避免上下文漂移。

双路本地推理

主 Agent 与独立审核可共享或拆分模型端点；已验证本地 Qwen 27B 与远程模型双路跑通。

ROADMAP & ACCEPTANCE

分阶段技术路线与量化验收标准

分阶段路线

  • A · 证据覆盖控制面：问题×来源覆盖矩阵、缺口驱动、Candidate Ledger
  • B · 信息空间发现：站点发现、跨引擎去重、转化效率
  • C · 受控自适应与数据闭环：证据收益反馈、检索策略自适应

量化验收标准

  • 状态与可追溯性：100% 结论可回溯到原文
  • 搜索质量：Precision@10、Must-find Recall@50、来源角色覆盖
  • 来源与证据覆盖：独立来源组、双源率、来源多样性
  • 转化与资源效率：证据利用率、Token 成本、有效运行率
安全边界：仅采集无需登录的公开页面；遵守 robots；不做绕过验证码或登录控制；SSRF / 重定向 / 资源上限全部确定性拦截。
