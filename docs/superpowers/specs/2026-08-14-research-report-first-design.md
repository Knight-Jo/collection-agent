# 情报调研 Agent 报告优先改造设计

## 目标

将现有以证据链完备度为中心的公开来源采集 Agent，调整为以信息调研和正式报告为中心的情报调研 Agent。用户只需提供主题，也可以附加调研目标、问题和范围；Agent 自主制定提纲、检索公开来源、提取信息、识别缺口并生成一份可直接交付的结构化公开信息调研报告。

安全抓取、文档归档、哈希校验、引文定位和多媒体提取继续作为底层可信能力，不在本轮重写。

## 本轮交付范围

本轮形成一个可独立验收的第一阶段版本：

1. 任务支持仅输入主题，用户问题变为可选约束。
2. Agent 在没有用户问题时自动生成 3–6 个调研问题。
3. 深度抓取默认关闭，显式选择深度抓取或 `deep` 报告时启用；普通任务仍可定向抓取发现的高价值附件。
4. 充分性从“所有事实统一双来源”调整为基于声明类型的验证规则。
5. 新增正式的 `research-report` 主产物，旧证据包仅保留只读兼容。
6. 为每份采集材料生成 1–5 星阅读推荐和一句话评价，并生成整个材料集合的导读摘要。
7. 工作台默认展示调研报告，来源和证据作为辅助视图。
8. 保持现有任务 JSON 可读取；新字段提供默认值，不要求迁移历史数据。

本轮不增加新的搜索引擎、数据库、队列系统或模型供应商，也不重写 PDF、Office、OCR 和音视频处理器。

## 用户输入

统一的任务输入包含：

```json
{
  "topic": "低空经济产业发展情况",
  "objective": "了解产业现状、政策、主要企业和投资趋势",
  "questions": [],
  "scope": {
    "time_range": "2024-2026",
    "geography": ["中国"],
    "languages": ["zh-CN", "en"]
  },
  "report_depth": "standard"
}
```

约束如下：

- `topic` 必填且去除首尾空白。
- `objective` 可选，用于说明调研用途和重点。
- `questions` 可选，最多 6 个；存在时作为必须回答的核心问题，Agent 可以补充必要的背景问题，但不得删除用户问题。
- `scope` 可选，仅保存用户明确给出的时间、地区和语言范围。
- `report_depth` 为 `brief`、`standard` 或 `deep`，默认 `standard`。第一阶段仅持久化该偏好并用于提示报告详略；现有安全预算仍作为硬上限，避免同时改造成本控制。
- `deep_crawl` 从常规用户输入中移除，但 CLI 和 API 暂时保留兼容字段作为高级覆盖项。

## 调研计划

`intel_plan` 继续负责创建任务和稳定 ID，但问题生成规则调整为：

- 用户提供问题时，原样保留并允许 Agent 补充，最终总数为 2–6 个。
- 用户没有提供问题时，Agent 根据主题、目标和范围生成 3–6 个可独立回答的问题。
- 问题应覆盖定义或背景、最新进展、关键主体或数据、影响与风险；具体组合由主题决定，不使用固定领域模板。
- 删除提示词和默认配置中针对低空经济、亿航和特定财经网站的硬编码。

计划创建后持久化在现有 `IntelTask.questions` 中。历史任务模型和读取路径保持不变。

## Agent 工作流

Agent 的逻辑流程改为：

```text
理解目标与范围
  → 创建调研计划
  → 按问题制定查询和来源类型
  → 搜索候选来源并筛选
  → 定向抓取、提取和归档
  → 保存关键发现与引用
  → 审查问题回答度、矛盾和来源风险
  → 对明确缺口补充检索
  → 生成并校验正式报告
```

现有工具函数继续复用。第一阶段不新增复杂编排框架，只进行以下收敛：

- 移除必须运行两轮挑战的要求。默认执行一次报告前审查；只有存在重大矛盾、无来源数字或未回答核心问题时才补充检索。
- 停止生成独立证据包和旧式结构化研判；历史产物只读兼容。
- 报告生成成功、引用校验通过且所有核心问题都有 `answered` 或 `partial` 结果后，任务可以完成并标记 `sufficient` 或 `with_gaps`。
- Agent 不因单个事实未达到双来源而阻塞整份报告，但必须在正文中使用正确归属并披露不确定性。

## 声明和来源验证

复用现有 `Fact`、`EvidenceSupport`、`SupportReview` 和文档归档模型，给事实增加声明类型：

- `primary`: 法规原文、政府文件、企业公告、财报等一手来源直接披露的事实。
- `corroborated`: 需要多个独立来源交叉验证的重大事实。
- `reported`: 新闻、机构或主体的单方陈述，报告必须注明归属。
- `inference`: Agent 基于多个已引用事实形成的分析判断。

验证规则：

- `primary` 可由一个匹配且权威的一手来源支持。
- `corroborated` 默认需要两个独立来源组，至少一个高质量来源。
- `reported` 可由一个来源支持，但必须保留 attribution，不能写成无条件事实。
- `inference` 不直接绑定网页引文，必须绑定至少两个已验证事实并标注置信度和推理依据。
- 市场规模、融资金额、经营数据和争议性结论默认使用 `corroborated`；若只有原始报告或财报，则可使用 `primary` 并明确统计口径和来源。
- 相互冲突的数字不合并，分别记录并在报告中解释来源和口径。

现有严格引文蕴含审核继续保留，用于确认引文是否支持声明文本。

## 材料阅读推荐

每份进入任务资源列表的采集材料都生成一个任务级 `MaterialReview`。推荐结果属于“该材料对当前调研任务的阅读价值”，不是材料的绝对质量或事实可信度评级。同一材料用于不同主题时可以得到不同星级。

`MaterialReview` 包含：

- `task_id`: 当前调研任务 ID。
- `document_id`: 已归档材料 ID；未成功归档时为 `null`。
- `canonical_url`: 抓取资源的规范 URL，用于关联未成功归档的材料。
- `rating`: 1–5 的整数星级。
- `description`: 不超过 120 个汉字的一句话评价，概括材料内容、阅读价值和必要的来源局限。
- `question_ids`: 该材料能够帮助回答的调研问题 ID。
- `created_at`: 生成时间。
- `updated_at`: 最近一次重算时间。

统一评级标准为：

- 5 星：直接支撑至少一条审核结果为 `full` 的当前任务事实，建议优先精读。
- 4 星：已作为当前任务候选证据使用，但尚无 `full` 支撑。
- 3 星：正文可读，标题或正文与当前主题及问题匹配，可补充背景。
- 2 星：正文可读并已归档，但与核心问题的直接关联有限。
- 1 星：正文不可用，或采集、下载、提取失败，可以跳过。

第一阶段评分采用上述可复现规则，不额外调用评分模型。系统只向用户展示一个星级，不再增加可信度、质量或优先级等平行标签。局限性统一写入 `description`。

材料评价按任务存储，不写入全局 `IntelDocument`，避免跨主题复用时继承错误评分。抓取或提取失败的材料仍显示在资源列表中，固定为 1 星并说明失败原因。

全部材料评价完成后生成一个任务级 `MaterialDigest`，包含：

1. 材料数量、主要类型、时间范围和来源构成的简要概览。
2. 已验证材料共同呈现的最多 5 条核心信息。
3. 4–5 星材料组成的优先阅读清单。
4. 按调研问题组织的建议阅读顺序。
5. 重复材料、来源分歧和仍然缺失的信息。

材料导读作为调研报告中的独立章节，同时通过任务详情 API 返回，供工作台在资源列表上方展示。

## 问题回答度与停止条件

问题状态调整为：

- `answered`: 已形成明确回答，并满足该回答中关键声明各自的验证规则。
- `partial`: 有可用信息，但范围、时效、来源或数据仍存在明确缺口。
- `unanswered`: 尚无足以写入报告的信息。
- `conflicted`: 关键来源存在未解释的实质冲突。

任务停止条件为以下任一项：

1. 所有核心问题均为 `answered`。
2. 所有核心问题至少为 `partial`，且连续两轮没有新增高价值来源或关键发现。
3. 达到任务预算，并已记录未回答问题和原因。

新增事实不会因为暂时缺少第二来源而直接增加整个任务的失败分。覆盖快照仍保留，用于历史任务兼容和审计，但新的完成判断以问题回答度为主。

## 正式调研报告

新增 `ResearchReportInput`、`ResearchReportSection` 结构化输入模型和 `generate_research_report` 生成器。报告包含：

报告输入只选择已验证的事实和分析关系；执行摘要、转述归属、推理依据和局限由系统根据证据与最新覆盖状态生成，模型不能直接提供待发布的 URL、引用或内部 ID。

1. 标题与调研范围
2. 执行摘要
3. 按调研问题组织的核心发现
4. 来源分歧与不确定性
5. 局限和信息缺口
6. 综合结论
7. 材料导读与优先阅读清单
8. 去重后的来源目录

每个可核验的重要事实必须引用已归档文档。引用由系统根据事实和证据 ID 生成，模型不能手写不存在的 URL、标题或引文。报告正文不展示内部 task、fact、document 或 coverage ID；这些信息仅保留在证据附件和任务详情中。

产物路径为：

```text
output/{topic}-research-report.md
```

现有 `assessment` 读取接口在兼容期内返回同一报告，新增正式的 `report` artifact 类型。升级前生成的 `package` 只读保留，不再生成新附件。

## 搜索、抓取与多媒体

- `crawl.enabled_by_default` 改为 `false`。第一阶段使用定向 `web_fetch`；显式选择高级深度抓取或 `report_depth=deep` 时才启用递归队列。由 Agent 根据检索缺口动态开启递归队列属于第二阶段。
- 普通检索先筛选候选 URL，再定向抓取；深度抓取只在发现高价值入口页、附件目录或普通检索不足时启用。
- 继续执行 robots、SSRF、防重定向攻击、域名限速和字节预算。
- PDF、Office、图片、音频和视频继续归档并提取为可搜索文本。
- OCR 引用使用行号；音视频转写引用保留时间戳。
- 处理器缺失或提取失败的资源可以进入来源附件列表，但不能支持报告声明。

## API 与工作台

`POST /api/runs` 接受新的可选输入字段，同时兼容旧的 `questions` 和 `deep_crawl` 请求。

新增主产物接口：

```text
GET /api/tasks/{task_id}/artifacts/report
```

任务详情接口新增 `material_digest`，资源项新增 `rating` 和 `description`；直接抓取材料与递归抓取材料使用同一资源列表和安全下载入口。SSE 保留现有运行、工具和采集事件，工作台将材料导读与报告工具映射为面向用户的进度文案。

工作台变更：

- 新建任务只要求主题。
- 调研目标、问题、时间、地区和语言作为可选设置。
- 深度抓取移动到高级设置。
- 任务详情默认打开调研报告。
- 证据链和采集资源继续作为辅助标签。
- 采集资源按星级从高到低展示，每项显示星级和一句话评价。
- 资源列表上方展示材料集合摘要、优先阅读清单和按问题组织的阅读建议。
- 用户界面不以 `gap_score` 作为主要成果指标，改为显示核心问题回答情况和来源数量。

## 错误处理

- 无法生成任何可引用发现时，任务失败并返回稳定错误码 `NO_REPORTABLE_FINDINGS`。
- 部分问题无法回答时，仍生成报告，任务状态为 `completed_with_gaps`，并在报告中列明缺口。
- 报告引用不存在、文档哈希变化或引用未通过审核时，拒绝完成任务。
- 取消任务继续终止下载、OCR、Office 转换和音视频转写子进程。

## 测试与验收

后端必须覆盖：

- 只提供主题可以创建任务并自动生成问题。
- 用户问题保持原文且可补充问题。
- 一手来源声明可以在单个权威来源下通过。
- 需要交叉验证的声明仍要求独立来源。
- 新增单源有效事实不会使任务整体完成度倒退。
- 报告包含所有核心问题、引用和来源目录。
- 报告不存在伪造 URL、无效 evidence ID 或内部实现 ID。
- 部分问题无法回答时生成 `with_gaps` 报告。
- 每个采集资源都有 1–5 星推荐和不超过 120 个汉字的评价。
- 同一文档在不同任务中的推荐结果相互独立。
- 提取失败的资源为 1 星且评价包含失败原因。
- 材料导读只引用当前任务资源，并正确列出 4–5 星优先阅读材料。
- 历史任务 JSON 仍能读取。

前端必须覆盖：

- 仅填写主题即可提交。
- 可选问题和范围正确传给 API。
- 任务完成后默认显示调研报告。
- 资源列表显示星级和简短评价，并默认按星级排序。
- 材料导读摘要和优先阅读清单可见。
- 报告缺失、任务有缺口和来源下载错误均有明确状态。

全量验收运行 Ruff、Pyright、pytest、Python 构建，以及 Bun 测试、类型检查和生产构建。

## 实施分解

本设计拆为三个连续阶段：

1. **主题驱动与报告主产物**：输入模型、自动计划、声明类型、报告生成、API 和报告优先 UI。
2. **自适应研究循环**：在第一阶段最小回答度和停止规则之上，增加动态来源策略、运行中按需开启递归抓取，以及面向用户的阶段事件。
3. **多媒体信息增强**：表格结构化、图片图表理解、带时间戳的音视频引用。

第一阶段完成后系统即可按新定位交付调研报告；第二、三阶段在真实实验数据证明存在对应瓶颈时继续实施。
