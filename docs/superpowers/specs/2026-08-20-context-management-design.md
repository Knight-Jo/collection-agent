# 有界上下文管理设计

## 目标

让情报调研 Agent 在 32K、64K、128K、256K 模型上下文中均能通过配置选择安全工作窗口，避免长期搜索、网页正文和语义审核导致上下文溢出，并继续以本地持久化事实和证据完成任务。

## 设计

新增 `context` 配置。`context_window_tokens` 只接受 32768、65536、131072、262144；历史字节预算默认为窗口 token 数的 1.5 倍，单次工具正文预算默认为窗口 token 数的四分之一并限制在 8–64KiB。主模型和审核模型分别具有输出 token 上限，本地推理模型可显式关闭 thinking。

主 Agent 使用 Pydantic AI `ProcessHistory`。处理器保留初始任务请求、最近完整交互和最新请求，在每次模型调用前删除旧历史，并加入由本地 task/document/fact/evidence/review/coverage 状态确定性生成的短快照。快照按当前阶段只给出一个下一动作：搜索转抓取、归档转阅读、阅读转事实/证据、待审证据转审核、审核转覆盖评估、覆盖停止转研判、材料导读转报告、报告转完成。原始网页、搜索矩阵、文档、事实和证据继续保存到现有文件存储，不使用模型摘要作为长期记忆。

`web_search`、`web_fetch` 和 `document_read` 返回受配置限制的工作片段；完整内容不删除。连续获得可抓取搜索候选但未执行抓取达到阈值时，搜索工具返回阶段转换错误，要求先抓取和取证。

语义审核保持独立 Agent，每次只接收一个事实及其待审核引文，并应用独立输出上限。关闭 thinking 通过 OpenAI 兼容请求的 `chat_template_kwargs.enable_thinking=false` 实现，仅在配置显式开启时发送。

runner 共享同一 `RunUsage`、依赖状态和压缩消息历史。模型在任务未完成时只输出自然语言，runner 会自动追加继续指令，直到任务进入 `done` 或累计请求预算耗尽。`intel_plan` 对未完成任务幂等，因此重启后再次执行同一任务不会覆盖活动任务。

报告工具允许事实结论省略可推导的 `kind`；系统依据事实类型和覆盖状态自动选择直接事实或带来源归属的转述。未回答问题保留空结论章节并在报告中明确写为“未形成可验证结论”，使 `done/with_gaps` 不依赖伪造内容。

## 验收

- 四个上下文档位均可解析，其他值配置失败。
- 历史处理后不超过派生字节预算，并保留初始任务、最新请求和本地状态快照。
- 工具调用与返回在裁剪后保持成对；超大正文不会完整进入模型历史。
- 主模型和审核模型分别应用配置的输出上限。
- 本地 Qwen3.5-9B 在 32K 档位完成真实任务，或在外部搜索质量不足时诚实以 `done/with_gaps` 收尾，不再因上下文超限退出。

## 实测结果

同一 32K Qwen3.5-9B 任务在基线中因 32,870 token prompt 超限失败。启用本设计后，任务经中断恢复生成 3 条审核记录和正式报告，最终状态为 `done/with_gaps`；最后一次恢复仅使用 3 个模型请求和 16,566 tokens，且未新增搜索。
