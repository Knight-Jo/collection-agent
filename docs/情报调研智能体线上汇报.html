WHY NOW

公开信息不缺，真正稀缺的是：把信息变成可信结论，并让每个结论都能回到原始材料。

海量网页、附件与多媒体持续增长

03 / 18

THE PROBLEM

传统人工调研与通用云端 Agent，各自都有明显断点

人工方式

耗时长、方法难复用

  • 搜索、下载、摘录、交叉核对高度依赖个人经验
  • 专题跨度大时容易遗漏附件、外文来源和反方材料
  • 人员变化后，来源体系与调研过程难以继承
通用云端 Agent

回答快，但成果控制力不足

  • 常以对话答案为终点，原件、过程和审核状态留存不足
  • 搜索摘要、网页原文和模型判断之间的边界不够透明
  • 数据位置、模型选择、访问预算和业务规则受平台约束
甲方需要的是一条完整生产线：自主检索 + 多媒体采集 + 证据核验 + 正式报告 + 本地沉淀。

OBJECTIVES

广

扩大来源覆盖

深

深入原始材料

真

形成审核证据

事实必须绑定可定位引文，重大结论要求独立来源验证。

用

面向阅读交付

生成管理层报告，并为每份材料给出 1—5 星阅读推荐。

目标不是“搜到最多”，而是在受控预算内获得更多可支撑结论的独立证据。

DESIGN PRINCIPLES

让模型负责判断，让程序守住底线

Agent 擅长的部分

理解、规划与选择

  • 理解主题并拆解核心调研问题
  • 选择查询词、材料和下一步行动
  • 识别信息缺口、矛盾与潜在解释
  • 组织面向管理者的报告结构
确定性程序负责的部分

校验、限制与留痕

  • URL 安全、robots、并发和字节预算
  • 原件归档、哈希、引文逐字定位
  • 来源独立性、证据审核和覆盖门槛
  • 上下文裁剪、断点恢复和报告完整性
关键原则：模型可以建议结论，但不能绕过证据工具把未经验证的信息写入正式报告。

代码对应：agent.py、task.py、evidence.py、audit.py、coverage.py、report.py。

可解释

可约束

DEEP CRAWL & JS

从“搜索结果页”继续走向真实内容

持久化递归采集

  • 搜索结果播种队列，继续发现页面与附件链接
  • URL 规范化、任务内去重、跨任务缓存和条件重验
  • 默认最大 200 个 URL、全局并发 4、单域并发 1
  • 遵守 robots.txt，单域请求间隔默认至少 1 秒

按需 JavaScript 渲染

  • 静态 HTML 无有效正文时识别页面壳并启用 Chromium
  • 渲染后复用正文提取、链接发现和证据审核流程
  • 限制单页时间、请求数、下载字节和浏览器并发
  • 保留原始响应与渲染 DOM 双哈希，结果可核查
200默认任务 URL 上限
4抓取全局并发
1单域并发 / 浏览器并发
1 GiB默认任务总下载上限

代码与配置：crawl.py、browser.py、fetch.py、security.py、config.example.yaml。

EVIDENCE BY DESIGN

正式结论必须穿过四道门

01 / FACT

原子事实

把复合陈述拆成可单独验证、可替换的事实单元。

02 / QUOTE

精确引文

引文必须逐字存在于已归档正文，并记录起止行号。

03 / REVIEW

隔离审核

独立审核模型判定 full、partial、irrelevant 或 contradicts。

04 / COVERAGE

覆盖门控

按来源独立性、质量、时效和冲突判断是否可进入报告。

完整追溯链：报告结论 → Fact ID → Evidence ID → 原文行号 → Document ID → 原件与正文 SHA-256。

代码对应：fact.py、evidence.py、audit.py、conflicts.py、coverage.py、storage.py。

DELIVERABLES

同时服务“快速决策”和“深入核查”

管理层主产物

结构化公开信息调研报告

  • 执行摘要、调研范围和按问题组织的核心发现
  • 综合结论、分歧、不确定性与明确局限
  • 系统生成编号引用，避免模型手写失效链接
  • 证据不足时以 with_gaps 诚实交付，不编造完整答案
业务人员辅助产物

1—5 星材料导读

  • 5 星：直接支撑审核通过的核心发现
  • 4 星：已作为候选证据使用，值得重点核查
  • 3 星：与主题相关，适合作为背景材料
  • 1—2 星：低相关或正文不可用，可降低阅读优先级
同一材料在不同任务中可获得不同星级——推荐的是对当前问题的阅读价值，而不是笼统的机构可信度。

代码对应：materials.py、report.py、web/views.py；主报告路径 output/{topic}-research-report.md。

RECOMMENDATION

下一阶段：不再单纯扩大抓取量，重点提高每次搜索的证据收益

P0

搜索质量闭环

建立“问题 × 来源角色 × 时间 × 证据缺口”覆盖矩阵，用缺口决定下一次查询和停止时机。

P1

候选治理与站点发现

统一候选台账、跨引擎去重、域名公平排序，并发现 Sitemap、RSS、下载中心和 IR 页面。

P2

证据转化与评测

优先阅读可补充独立验证的材料；量化 Precision@10、Recall@50、证据利用率和双源率。

选择我们，不只是选择一个模型；而是选择一套甲方可掌控、可审计、可持续积累的情报生产能力。

建议以真实业务主题继续试用验收，按“结论有效性、独立证据覆盖、材料阅读价值和报告可复核性”评价项目成效。
