# 情报调研智能体能力边界、建设状态与缺口报告

**文档用途：** 项目汇报、建设决策、阶段评审与后续研发任务分解  
**适用范围：** 面向无需登录的互联网公开信息，完成主题检索、材料采集、内容提取、证据核验和结构化调研报告交付  
**评估时间：** 2026 年 8 月

---

## 一、报告摘要

本项目建设目标不是提供一个普通的联网问答模型，而是形成一套可在本地部署、能够持续执行公开信息调研任务的情报生产系统。

系统以 Agent 作为调研组织者，根据主题和核心问题自主选择查询、来源、材料和下一步行动；以确定性工具负责网络安全、原件归档、事实与引文、语义审核、覆盖判断和报告完整性；以本地工作区保存任务状态、原始材料、证据和最终报告。

当前系统已经形成从主题输入到报告输出的完整主链，并在云端模型和本地 Qwen 27B 模型上完成真实任务运行。证据治理、正式报告、任务恢复和本地工作台已经达到真实专题验证阶段；通用搜索、递归采集和多媒体处理具备可用能力；垂直搜索、真实动态网页、多格式样本集和正式评测仍需进一步完成端到端验证。

从整体成熟度判断，项目目前处于 **M3“真实任务验证”阶段**，尚未达到 M4“正式验收与稳定试运行”。当前工作的重点已经从“功能是否存在”转为以下四个问题：

1. 搜索是否能够稳定找到必查来源和不同来源角色；
2. 网页、附件和多媒体是否能够在真实互联网环境中稳定内容化；
3. 重要结论是否满足独立来源、精确引用和人工复核门槛；
4. 本地模型是否能够以可接受的时间、Token 和人工修改量稳定交付报告。

## 二、能力边界

### 2.1 一期能力范围

一期系统面向单机、单工作区、单业务用户，重点建设以下能力：

- 主题式公开信息调研，可选核心问题、目标、时间、地区和语言范围；
- 通用搜索、新闻、学术、软件、官网、附件和历史快照等公开来源发现；
- 静态网页、JavaScript 动态网页和公开附件采集；
- PDF、Office、TXT、CSV、图片 OCR、音频和视频内容提取；
- 原子事实、精确引文、独立语义审核、来源交叉验证和冲突管理；
- 覆盖评估、信息缺口、结构化调研报告和 1—5 星材料导读；
- 本地模型、上下文管理、本地 Web 工作台、API、SSE、取消和恢复；
- 实验运行、轨迹记录、评分表及云端与本地模型对比。

### 2.2 一期明确不包含

以下能力不属于当前一期范围：

- 登录网站、付费墙和交互式验证码绕过；
- 住宅代理池、浏览器指纹伪装等主动反爬规避；
- 多租户、复杂 RBAC、跨部门数据隔离和统一身份认证；
- 高可用集群、分布式任务队列、关系数据库和对象存储改造；
- 自动代替专业人员作出法律、投资、合规或对外发布决定；
- 未经授权接入内部文档、业务系统或非公开数据库。

这一边界用于避免把“互联网公开信息调研”无限扩展为通用数据平台。只有真实试运行证明存在明确需求后，相关能力才进入后续建设范围。

## 三、能力成熟度阈值

为避免将“写完代码”“自动测试通过”和“真实业务可用”混为一谈，本报告采用五级成熟度模型。

| 等级 | 名称 | 判定条件 | 可对外表述 |
| --- | --- | --- | --- |
| **M0** | 尚未建设 | 没有实现或只有设想 | 规划中 |
| **M1** | 功能实现 | 已有实现，能够在开发环境调用 | 已实现原型 |
| **M2** | 工程验证 | 自动化测试、边界与失败路径通过 | 已完成工程验证 |
| **M3** | 真实任务验证 | 在真实模型、真实公开网页和真实专题中产生可复核产物 | 已具备试验或演示能力 |
| **M4** | 正式验收 | 多主题、多次重复、人工盲审和性能安全门禁全部通过 | 可进入受控试运行 |

M4 不是“所有指标取平均后及格”，而是关键门槛全部满足。较快的速度不能抵消引用错误，材料数量不能抵消来源缺失，报告生成成功也不能抵消伪造来源或严重安全问题。

### 3.1 M4 核心验收阈值

| 维度 | 核心阈值 |
| --- | --- |
| 任务完成 | 10 个冻结专题中至少 9 个形成有效报告，任务成功率不低于 90% |
| 问题处理 | 成功任务的核心问题 100% 明确回答或明确披露缺口 |
| 问题质量 | 核心问题充分回答率不低于 85% |
| 结果可追溯 | 引用可复核率 100%，所有重要结论能够回到归档原文 |
| 引文准确 | 人工判定引文支持率不低于 95% |
| 来源验证 | 需要交叉验证的事实合规率 100%，关键数字双独立来源率 100% |
| 结果安全 | 伪造来源、URL、引文、数字和无依据重大结论均为 0 |
| 材料质量 | 有效材料率不低于 70%，噪声材料率不高于 15% |
| 动态网页 | 支持范围内动态页面提取成功率不低于 85% |
| 文档处理 | PDF 和现代 Office 总体提取成功率不低于 95% |
| 图片处理 | 文字型图片 OCR 可用率不低于 85%，纯照片正确跳过率不低于 90% |
| 安全与恢复 | SSRF、私网、恶意重定向和 robots 拒绝路径阻断率 100%；恢复成功率 100% |
| 本地模型 | Qwen 27B 双路上下文稳定，无 OOM；100 次模型请求错误率不高于 1% |
| 使用效果 | 初稿提效不低于 50%，材料筛选提效不低于 40%，业务评分不低于 4.0/5 |

- **尚未达到 M4**：项目缺少 10 个冻结专题的正式验收、稳定独立验证率、完整多媒体样本和单机长期试运行数据。

## 五、总体建设目标

系统总体目标仍然围绕“广、深、准、用”，但每个目标必须有可量化的能力阈值。

| 建设目标 | 目标定义 | 目标状态 |
| --- | --- | --- |
| **广** | 核心问题所需的一手、独立验证、结构化数据、新闻、学术、附件和反证来源均被纳入搜索空间 | 必查来源 Top50 召回稳定，来源角色完整，单域和同源转载不主导语料 |
| **深** | 系统能够从入口页进入真正承载信息的正文、附件、动态页面和多媒体原件 | 深层高价值材料可被发现、内容化、引用和复核，失败状态明确且可恢复 |
| **准** | 正式结论满足声明类型对应的证据门槛，并能披露单源、冲突、时效和信息缺口 | 引用可复核率 100%、支持率不低于 95%、交叉验证合规率 100%、重大错误为 0 |
| **用** | 用户能够快速阅读结论、选择材料、核查原文并复用任务成果 | 报告满足业务结构，平均评分不低于 4.0，初稿和材料筛选时间显著下降 |

最终建设目标不是让 Agent 无限自主，而是让它在清晰的任务、证据、安全和资源边界内完成尽可能高质量的调研。

## 六、分能力域现状、目标与缺口

### 6.1 主题任务与 Agent

**当前状态：M3，已完成主链。**

已落地内容：

- 支持只输入主题创建任务，也支持目标、核心问题、时间、地区、语言和报告深度；
- 用户显式给出问题时，问题文本、顺序和数量被确定性冻结；
- Agent 可以自主选择搜索、抓取、阅读、事实、证据、审核、覆盖和报告工具；
- 任务具有持久化预算、阶段门控、无进展停止和自动续跑能力；
- 模型提前结束、上下文裁剪或进程重启后，可以从任务状态继续。

建设目标：

- 在 10 个冻结专题中至少 9 个达到有效终态；
- 成功任务的所有核心问题均被明确回答或披露缺口；
- 不出现重复建任务、问题漂移、阶段死循环和无进展工具重复调用。

能力缺口与待完成内容：

- 当前成功运行仍集中在少量低空经济专题，跨领域稳定性不足；
- 小模型在复杂阶段仍可能重复审核、覆盖评估或尝试无效参数；
- 需要将错误类型、停止原因和阶段推进情况纳入 10 专题统计；
- 需要形成政策、企业、行业、技术、事件五类任务的稳定提示和动作基线。

### 6.2 通用搜索与查询控制

**当前状态：M3，能够支持真实任务，但召回稳定性仍不足。**

已落地内容：

- 支持 SearXNG、Bing、百度和新闻入口；
- 使用确定性查询矩阵覆盖一手来源、独立验证、结构化数据、附件、反证和多语言槽位；
- 对过宽查询、重复查询和连续只搜不抓进行程序门控；
- 搜索候选可直接播种递归采集队列；
- 已增加 URL 去重、相关性过滤、来源公平和单域占比约束。

建设目标：

- 每个核心问题的 Top10 结果相关率达到正式评测要求；
- 预先标注的必查来源在 Top50 中稳定召回；
- 必需来源角色得到覆盖，重复 URL、同源转载和低价值导航不占用主要预算；
- 搜索服务失败时快速降级，并保留失败来源和原因。

能力缺口与待完成内容：

- 需要为 10 个专题建立必查来源集和搜索结果人工标注；
- 搜索预算仍需根据问题数量、问题难度和剩余证据缺口动态分配；
- 需要统一候选台账，贯通“搜索到—已归档—已阅读—已取证—已拒绝”状态；
- 需要继续完善时间范围、地域和实体别名对查询生成的约束。

### 6.3 垂直搜索

**当前状态：M2，新增实现和自动化测试已经完成。**

已落地内容：

- 新闻检索采用国内可访问入口优先级联；
- 学术检索覆盖 arXiv、Crossref 和匿名 Semantic Scholar 补充；
- 软件检索覆盖 GitHub、Gitee、仓库和 Issue 等公开信息；
- 失效链接可尝试 Wayback 历史快照；
- Provider 注册时拒绝付费、需要密钥或不能匿名访问的能力；
- 覆盖评估发现新闻、学术或软件来源缺失时，可自动补充对应候选。

建设目标：

- 垂直来源能够针对适用问题带来可测量的关键事实或独立来源增益；
- Provider 失败、限流或网络不可达时能够在预算内降级；
- Provider 来源类型和证据角色能够稳定传递到归档文档和评测记录。

能力缺口与待完成内容：

- 最新垂直搜索代码晚于现有 052 号实验，尚未完成真实联网端到端复跑；
- 缺少“启用垂直搜索前后”的召回、来源多样性和证据产出对比；
- 需要验证国内网络环境下每个 Provider 的可用率、延迟、限流和缓存收益；
- 需要按专题适用性触发垂直能力，避免所有任务无差别调用全部 Provider。

### 6.4 递归与动态网页采集

**当前状态：M2+，递归采集已真实运行，动态网页主要完成工程验证。**

已落地内容：

- 持久化优先队列、父子来源链、深度、优先级、状态和下载字节记录；
- URL 规范化、任务内硬去重、跨任务缓存和条件请求；
- robots、单域并发、请求间隔、重试、单文件和总下载预算；
- DNS pinning、SSRF 防护和重定向逐跳校验；
- 静态正文不足时可按需启动 Chromium，保存渲染 DOM 并继续发现动态链接；
- 取消和处理失败时保留可恢复状态。

建设目标：

- 支持范围内动态页面提取成功率不低于 85%；
- 重复下载率不高于 1%；
- 10 次故障注入恢复成功率达到 100%；
- 四个不同域名的抓取峰值有效并发不低于 3，同时单域峰值始终为 1；
- 所有 robots 拒绝、私网地址、恶意重定向和超限请求均正确阻断。

能力缺口与待完成内容：

- 真实专题中的 JavaScript 页面样本不足，尚不能给出生产成功率；
- 当前全局字节锁会串行化实际下载，需要改为下载前额度预留、结束后按实际字节结算；
- 需要覆盖至少 3 个含动态页面的真实专题和 20 个动态页面专项夹具；
- 需要进一步验证浏览器 sandbox、请求旁路、iframe、WebSocket 和重定向路径。

### 6.5 多媒体处理

**当前状态：M2+，处理链路已打通，真实格式样本不足。**

已落地内容：

- 支持 PDF、DOC/DOCX、XLS/XLSX、PPT/PPTX、TXT 和 CSV；
- 支持 PNG、JPEG、WebP 和 TIFF 图片 OCR；
- 支持 MP3、WAV、M4A、OGG、FLAC 音频转写；
- 支持 MP4、WebM 和 MOV 视频音轨提取与转写；
- 支持 LibreOffice、Tesseract、FFmpeg 和 faster-whisper 处理路径；
- 处理器缺失时保留原件并标记不可用，不允许进入正式证据链；
- 已对页数、像素、文档容器、表格和子进程时间设置处理边界。

建设目标：

- PDF 和现代 Office 总体提取成功率不低于 95%；
- 文字型图片 OCR 可用率不低于 85%，纯照片正确跳过率不低于 90%；
- 清晰普通话音视频转写字词正确率不低于 80%；
- 95% 音视频片段时间戳误差不超过 2 秒；
- 原件归档完整率和处理器缺失状态准确率均为 100%。

能力缺口与待完成内容：

- 目前真实实验主要证明 PDF、图片和视频路径，Office 和独立音频公开直链样本较少；
- 需要建立覆盖各格式、正常值、边界值和超限值的固定夹具；
- 需要补充扫描 PDF OCR、表格结构和幻灯片页级定位的业务验收；
- 需要在共享加速器环境验证 Whisper 与本地模型的资源互斥和恢复策略。

### 6.6 证据治理

**当前状态：M3，是当前最成熟的核心能力之一。**

已落地内容：

- 事实按最小可验证陈述保存，并保留替换历史；
- 引文必须逐字存在于已归档正文，并记录行号或时间戳；
- 独立审核模型判断完整支持、部分支持、无关或矛盾；
- 审核并发、单次超时和增量保存均可配置；
- 支持一手事实、交叉验证事实、来源转述和分析推断的不同规则；
- 支持来源组、时间范围、冲突、覆盖缺口和停止原因；
- 报告只接受当前覆盖快照中满足门槛的事实。

建设目标：

- 引用可复核率 100%；
- 引文支持率不低于 95%；
- 交叉验证合规率 100%，关键数字双独立来源率 100%；
- 伪造来源、URL、引文、数字和无依据重大结论均为 0；
- 已知冲突和证据缺口在报告中披露率 100%。

能力缺口与待完成内容：

- 现有实验中的双源率仍不稳定，部分关键事实仍以单一来源交付；
- 同源转载、同一 URL 的多文档记录和来源集团血缘仍可能被误认为独立来源；
- 自动审核指标仍需要双人盲审校准，不能直接替代人工正确性判断；
- 需要建立关键数字、口径冲突、单方声明和推断结论专项基准。

### 6.7 报告与阅读辅助

**当前状态：M3，已在真实任务生成产物。**

已落地内容：

- 生成执行摘要、调研范围、按问题发现、综合结论、局限和来源目录；
- 充分和有缺口两种终态均可生成诚实报告；
- 事实、来源转述和分析推断采用不同呈现方式；
- 引用编号由系统根据已验证证据生成；
- 材料提供唯一的 1—5 星阅读推荐和一句话评价；
- 报告、覆盖快照和引用文档哈希绑定，材料变化后拒绝错误完成。

建设目标：

- 报告结构合法率 100%；
- 所有核心问题均有回答或明确缺口；
- 人工事实修改率不高于 10%；
- 业务人员评分不低于 4.0/5；
- 不作实质改写即可内部流转的报告比例不低于 80%。

能力缺口与待完成内容：

- 最新真实报告仍出现同一 URL 使用多个引用编号的问题；
- 部分任务虽生成报告，但结束清单和运行终态记录不完整；
- 综合结论和跨问题摘要的内容质量仍受模型能力和有效事实数量影响；
- 需要增加同一专题跨期更新、差异摘要和历史材料复用能力；
- 需要建立管理层摘要与研究员证据视图的分层验收。

### 6.8 本地模型与上下文

**当前状态：M3，本地模型已经跑通完整任务。**

已落地内容：

- 支持 OpenAI 兼容接口，可接入 llama-server、vLLM 和云端模型；
- 支持主模型与独立审核模型分别配置；
- 支持 16K、32K、64K、128K 和 256K 上下文档位；
- 自动压缩消息历史，并从持久化任务状态重建当前阶段；
- 主 Agent 和审核模型具有独立输出上限；
- 本地 Qwen 27B 已完成真实搜索、取证、审核、覆盖和报告闭环。

建设目标：

- 双路 256K 配置能够被正确识别并稳定运行；
- 64K、128K 和 224K 双路请求全部完成，OOM 和模型服务崩溃为 0；
- 双路合计 decode 速度 P50 不低于 45 token/s，P10 不低于 40 token/s；
- 100 次模型请求错误率不高于 1%，服务重启为 0；
- 本地模型总体质量保持率不低于云端基线的 90%，单项分类保持率不低于 85%。

能力缺口与待完成内容：

- 真实对比中，本地 Qwen 使用约 3 倍模型请求和 Token，效率仍需优化；
- 当前只有审核并发控制，尚未形成完整的双槽优先级调度和主 Agent 槽位保障；
- 需要在相同题目、搜索时段、预算和材料下完成每模型至少 3 次配对实验；
- 需要记录槽位启用率、排队等待、吞吐、显存、OOM 和每份有效报告成本；
- 蒸馏或微调前需先形成稳定教师轨迹和人工复核金标准。

### 6.9 Web、接口与可观测

## 九、项目阶段判断

### 9.1 已经具备的能力

- 可以从主题或固定问题启动完整调研任务；
- 可以完成公开搜索、原件归档、正文提取、事实和引文登记；
- 可以由独立模型审核证据，并按来源、时间和冲突判断覆盖；
- 可以在证据不足时诚实形成有缺口报告；
- 可以为材料提供 1—5 星阅读推荐和来源目录；
- 可以在本地 Qwen 27B 上完成真实任务闭环；
- 可以通过 Web 工作台观察任务、查看报告和下载材料；
- 可以记录实验轨迹并对云端与本地模型进行结构化比较。

### 9.2 尚未达到的能力阈值

- 尚未证明在 10 个不同类型真实专题中达到至少 90% 任务成功率；
- 尚未证明关键来源 Top50 召回、引文支持率和交叉验证合规率稳定达到正式门槛；
- 尚未完成动态网页、Office、音频和视频的规模化真实样本验收；
- 尚未完成本地 27B 双槽、长上下文和长期稳定性正式压测；
- 尚未形成足够的人工盲审数据支持模型选型、蒸馏或微调结论；
- 尚未完成长期试运行、用户满意度、人工修改率和业务提效复验。

### 9.3 总体结论

当前系统已通过“能否形成完整调研闭环”的验证，并形成了较清晰的工程架构和质量底座。项目最成熟的部分是证据治理和诚实报告，最需要继续建设的部分是多源搜索实效、真实动态与多媒体覆盖、本地模型效率和正式评测样本。

因此，当前适合的项目表述是：

> **核心能力已经落地并完成真实专题验证，项目整体处于 M3；下一步通过多主题、人工盲审和单机长期试运行，将能力推进到 M4 正式验收。**

后续建设应坚持“证据质量优先于材料数量、安全门槛优先于速度、真实任务优先于演示样例”。只有当“广、深、准、用”的关键阈值均能从系统记录和人工评分中复算，才能认定系统具备稳定业务使用能力。
