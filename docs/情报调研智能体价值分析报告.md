# 本地情报调研智能体价值分析报告

## 一、报告摘要

本项目建设的不是一个通用聊天机器人，而是一套面向公开信息调研任务的本地化智能生产系统。用户只需给出调研主题，智能体即可自主拆解问题、检索互联网公开来源、抓取和归档材料、提取关键事实、核验证据、识别分歧，并最终形成结构化公开信息调研报告。

相较于常见的通用云端智能体，本系统的核心价值不在于“回答得更像人”，而在于把一次性的模型回答转化为可控制、可复核、可追溯、可持续积累的情报成果。其主要差异体现在以下方面：

1. **从回答问题升级为交付调研成果**：主产物是正式报告、材料导读、来源目录和可审计证据链，而不是一段无法复核的对话文本。
2. **数据和成果沉淀在甲方本地**：任务状态、原始材料、提取正文、事实、引文、审核结果和报告均保存在本地工作区，便于内部留存、复用和审计。
3. **事实必须经过证据约束**：搜索摘要不能直接成为证据；只有完成原文归档、精确引文定位和语义审核的内容，才能进入正式结论。
4. **能够处理网页之外的真实材料**：除 HTML 页面外，系统还可发现、归档并处理 PDF、Office、图片、音频和视频等材料。
5. **围绕甲方业务持续定制**：当前已开放搜索入口、重点来源、模型、预算和采集范围配置；报告模板及后续业务接口可在本地代码基础上按需扩展，不受通用云端产品固定流程限制。

因此，在公开信息专题调研、行业研究、政策跟踪、企业与事件研究、竞争情报和舆情背景调查等场景中，本系统具备替代通用云端智能体承担“正式情报调研工作”的条件。需要明确的是，它替代的是云端智能体的专项调研工作流，而不是替代所有通用问答、办公协同或互联网搜索产品。

## 二、需求理解

甲方真正需要的通常不是“模型给出一个答案”，而是以下可交付能力：

- 面对一个主题，能够主动规划需要调查的问题，而不是要求用户提前设计完整提示词。
- 能够从大量公开网页和附件中筛选与任务相关的材料。
- 对重要事实保留原始来源、原文引文和采集时间，支持事后核查。
- 对单方陈述、重大数据、一手披露和分析判断采用不同验证规则。
- 明确指出信息缺口、来源冲突和无法确认的内容，避免用流畅表达掩盖不确定性。
- 将成果整理为适合管理层阅读的报告，同时保留供业务人员深入查阅的原始材料。
- 使每次调研形成甲方自己的信息资产，而不是任务结束后只留下云端对话记录。

围绕这些需求，本项目采用“Agent 自主驱动 + 本地证据底座 + 报告优先交付”的总体思路。

## 三、总体设计思路

### 3.1 Agent 驱动，而非固定脚本

系统由 Agent 根据主题、目标、时间、地区、语言和报告深度自主组织调研流程。没有用户问题时，Agent 自动形成核心问题；存在明确问题时，则保留用户问题并补充必要的调查维度。

这种方式兼顾了智能性与流程约束：模型负责理解主题、选择查询和判断下一步行动，工具负责执行搜索、抓取、存储、审核和报告生成。模型不能绕过工具直接伪造来源或修改底层状态。

### 3.2 报告优先，证据链作为质量底座

系统最终交付的是结构化公开信息调研报告。报告包含执行摘要、调研范围、按问题组织的核心发现、综合结论、分歧与不确定性、局限、材料导读和来源目录。

报告中的引用由系统根据已验证事实自动生成，Agent 只能选择已验证事实及其分析关系，不能手写待发布的 URL、引用编号或内部 ID。报告生成后还会绑定最新覆盖状态、报告哈希和引用文档哈希；如果证据、冲突、文档或报告在完成前发生变化，系统拒绝将任务标记为完成。

### 3.3 分层采集，兼顾效率与覆盖

常规任务先通过搜索筛选候选来源，再对高价值页面和附件进行定向抓取。对于入口页、附件目录或普通检索难以覆盖的主题，可启用持久化深度采集队列，递归发现公开网页及材料。

深度采集支持断点恢复、任务内去重、跨任务缓存、条件请求、重试、全局与单域并发控制、单域访问间隔、robots.txt 和总下载预算。这样既避免无边界遍历全网，也为复杂专题提供比单次搜索更完整的材料覆盖。

### 3.4 声明分级，而不是统一套用一个可信度分数

系统按声明性质决定验证要求：

- `primary`：法规、公告、财报等一手材料直接披露的事实，可由匹配的一手来源支持。
- `corroborated`：重大数字、争议性事实或需要交叉验证的判断，要求多个独立来源组支持。
- `reported`：机构、媒体或主体的单方陈述，可以保留，但报告必须明确为来源转述。
- `inference`：系统形成的分析判断，必须绑定至少两个已经满足各自验证规则的事实，并明确标识为分析判断。

这种设计比给所有信息增加一个笼统“可信度标签”更容易解释，也更符合实际调研工作中不同材料、不同声明的使用方式。

### 3.5 面向阅读决策，而不是继续增加评分维度

系统对每份材料提供唯一的 1—5 星阅读推荐和一句话评价。星级表达的是“该材料对当前任务的阅读价值”，不是对发布机构作绝对可信度评级：

- 5 星：直接支撑审核通过的当前任务核心发现，建议优先精读。
- 4 星：已经作为候选证据使用，但尚未形成完整支撑。
- 3 星：与主题及问题相关，可补充背景。
- 2 星：正文可读，但与核心问题关联有限。
- 1 星：采集、下载或提取失败，可以跳过。

同一份材料用于不同主题时可以获得不同推荐结果，从而真正帮助用户决定“先读什么、为什么读”。

## 四、当前已经完成的工作

### 4.1 主题式调研任务

- 支持仅输入主题创建任务。
- 支持可选的调研目标、核心问题、时间范围、地区、语言和报告深度。
- Agent 可自主生成并持久化核心问题。
- CLI 与本地 Web 工作台共用同一任务运行器和数据模型。

### 4.2 公开信息搜索与安全抓取

- 支持 SearXNG、Bing、百度和百度新闻等公开搜索入口的组合使用。
- 支持定向抓取及可选的持久化递归采集队列。
- 对 URL、DNS 解析和每次重定向执行公网地址校验，降低 SSRF、DNS rebinding 和恶意重定向风险。
- 深度采集遵守 robots.txt，并执行域名限速、并发控制、下载上限、失败重试和缓存复用。
- 自动规范化 URL，减少追踪参数、片段、默认端口和查询顺序造成的重复采集。

### 4.3 多类型材料归档与内容提取

- 网页：HTML 正文、发布时间和外链提取。
- 文档：PDF、DOC/DOCX、XLS/XLSX、PPT/PPTX、TXT 和 CSV。
- 图片：PNG、JPEG、WebP、TIFF，可通过 Tesseract OCR 提取文字。
- 音频：MP3、WAV、M4A、OGG、FLAC，可通过 FFmpeg 与 faster-whisper 转写。
- 视频：MP4、WebM、MOV，可提取音轨后转写。
- 旧式 Office 文件可通过 LibreOffice headless 转换。
- 本地处理器不可用时仍保留原件，但提取状态标记为不可用，不能进入证据链。

所有成功归档的材料均保存原件、提取正文及 SHA-256；对高风险文档处理设置了页数、容器展开量、像素和处理时间等边界。

### 4.4 事实、证据和冲突管理

- 将调研发现保存为原子事实，避免把多个无法分别验证的结论混在一起。
- 引文必须逐字存在于已归档正文，并保存对应行号；音视频转写保留时间戳文本。
- 独立语义审核模型逐条判断引文是完整支持、部分支持、无关还是矛盾。
- 对相反证据和来源冲突单独登记、消解或披露，不允许静默合并冲突数字。
- 覆盖评估持续判断每个核心问题是已回答、部分回答、未回答还是存在冲突，并控制继续检索或停止。

### 4.5 正式报告和材料导读

- 自动生成带编号引用的 `research-report.md`。
- 执行摘要、来源归属、推理依据和局限由系统根据已验证事实及覆盖状态生成。
- 每份材料生成 1—5 星阅读推荐和简短评价。
- 对全部材料生成集合摘要、核心内容、优先阅读清单和信息缺口。
- 报告、材料原件和兼容的证据包均可通过本地 API 安全读取或下载。

### 4.6 本地工作台与运行控制

- 提供 FastAPI 后端和 React/Vite 本地工作台。
- 支持任务创建、任务列表、任务详情、报告查看、材料列表、材料下载和运行取消。
- 通过 SSE 实时展示 Agent 运行、工具调用和深度采集进度。
- `/api/system` 显示模型、搜索以及 Tesseract、FFmpeg、Whisper、LibreOffice 等处理器状态。
- 取消任务时同步终止下载、OCR、Office 转换和音视频转写子进程。

## 五、总体架构与数据流

```text
用户主题与调研约束
        ↓
Agent 规划核心问题与来源策略
        ↓
公开搜索 → 定向抓取 / 持久化深度采集
        ↓
原件归档 → 文本/OCR/转写 → SHA-256 完整性校验
        ↓
原子事实 → 精确引文 → 独立语义审核 → 冲突与覆盖评估
        ↓
材料 1—5 星导读 → 结构化公开信息调研报告
        ↓
本地 Web 工作台 / API / Markdown 产物
```

系统采用单机工作区架构，核心状态以原子 JSON 保存，原件和提取文本保存于本地文件系统。当前实现不依赖 Celery、Redis、Scrapy 或外部业务数据库，部署链路较短，便于在甲方环境内快速安装、验证和维护。

## 六、与通用云端智能体的功能对比

下表中的“通用云端智能体”指常见的 SaaS 问答或在线深度研究产品的一般形态，不针对某一家厂商；具体采购时仍应以候选产品当期能力和合同条款为准。

| 对比维度 | 本地情报调研智能体 | 常见通用云端智能体 | 对甲方的价值 |
| --- | --- | --- | --- |
| 产品定位 | 围绕公开信息调研形成正式成果 | 面向广泛问答、写作和临时研究 | 流程更贴近专题调研和情报生产 |
| 部署位置 | Agent、工作台、状态和材料库部署在甲方环境 | 服务主体通常运行在供应商云端 | 运行环境与成果资产由甲方掌控 |
| 数据留存 | 原件、正文、事实、引文、审核和报告本地持久化 | 通常以会话、导出文件或厂商空间留存 | 可形成长期、可复用的内部情报资产 |
| 证据约束 | 搜索摘要不能作为证据；必须归档、定位引文并审核 | 常见产品通常直接生成带链接的答案 | 更便于复核、审计和责任说明 |
| 报告完整性 | 报告绑定覆盖快照、报告哈希和引用文档哈希 | 通常缺少面向甲方的本地完整性门禁 | 防止材料变化后仍交付过期结论 |
| 来源冲突 | 显式登记相反证据和冲突状态 | 多数产品在答案中自然语言概括 | 避免不同口径被模型自动“平均” |
| 多媒体采集 | 网页、PDF、Office、图片 OCR、音视频转写统一归档 | 能力依产品和上传限制而异 | 更适合处理真实业务材料集合 |
| 递归发现 | 可选持久化队列、断点恢复、去重、缓存和限速 | 多为一次性在线搜索过程 | 适合附件目录和复杂站点的持续采集 |
| 阅读辅助 | 每份材料提供任务相关的 1—5 星推荐和简评 | 常见形态以引用列表为主 | 管理者快速掌握结论，业务人员快速选择原文 |
| 安全抓取 | DNS pinning、SSRF 防护、逐跳重定向校验、robots 和预算 | 安全策略由供应商实现且通常不可见 | 安全边界可检查、可测试、可调整 |
| 过程控制 | 搜索、抓取、模型请求、字节和并发预算可配置 | 通常由产品套餐或平台规则决定 | 成本、访问强度和任务范围可预测 |
| 模型选择 | 使用 OpenAI 兼容接口，可配置主模型和独立审核模型 | 通常绑定厂商模型体系 | 可按成本、中文能力、合规要求替换模型 |
| 来源策略 | 可配置甲方重点政策、企业 IR、行业和金融来源 | 通用来源策略通常不可深度定制 | 能积累甲方自己的行业调研方法 |
| 系统集成 | 提供本地 API、SSE、文件产物和结构化状态 | 取决于厂商 API、配额和授权 | 便于接入内部门户、档案和业务系统 |
| 私有化扩展 | 代码、流程和数据模型均可继续定制 | 深度定制通常受 SaaS 产品边界限制 | 核心能力不受单一供应商路线约束 |
| 本地闭环能力 | 接入本地模型和内网检索后，模型推理与材料处理可不依赖第三方云服务 | 通常依赖公网云服务 | 可服务高敏感和隔离网络场景；公开网页采集仍需受控网络出口 |

## 七、为什么优先选择本系统

### 7.1 甲方获得的是情报资产，而不是一次性答案

云端智能体最容易被替换的部分是模型生成能力，而最难替换的是甲方长期积累的来源体系、任务历史、原始材料、验证规则和专题知识。本系统将这些内容保存在甲方环境，使每次调研都能增加内部资产，而不是重复从零开始。

### 7.2 结果能够经受复核

管理决策、对外汇报和正式研究最怕“结论看起来合理，但无法解释从哪里来”。本系统保留事实到引文、引文到文档、文档到原件哈希的完整关系，并由独立审核模型检查引文是否真正支持事实。其成果更适合进入正式工作流程。

### 7.3 针对情报工作的过程可以固化

当前系统已经能够固化重点来源、声明验证标准、采集预算和报告完整性规则；关键词体系、报告模板及审批要求可在后续二次开发中继续纳入。人员变化后，调研方法仍然能够保留；不同人员和不同模型执行时，也可遵循相同的底线规则。

### 7.4 复杂材料不会停留在“链接列表”

公开信息中的关键内容经常藏在 PDF 附件、财报表格、政策扫描件、发布会视频或访谈音频中。本系统以“原件归档 + 内容提取 + 可搜索正文”为统一路径，为后续引用、复核和再利用提供基础。

### 7.5 可控性与可演进性更强

系统不依赖重量级分布式组件，适合先在单机环境形成稳定能力；同时模块边界清晰，可以在真实业务量增长后逐步替换存储、队列、模型和检索组件。甲方可以根据实际价值分阶段投入，避免一开始建设过重的平台。

### 7.6 模型不是唯一核心竞争力

本系统把主模型定位为调研编排者，把搜索、抓取、提取、证据审核、完整性校验和报告生成交给受约束工具。未来即使基础模型发生变化，甲方已经形成的材料库、证据链、流程和接口仍然可用，降低对单一模型供应商的依赖。

## 八、本地专用部署的特殊优势

1. **数据主权**：任务主题、调研范围、来源偏好、下载材料和产出报告由甲方保管。
2. **内部策略可保密**：重点关注对象、监测方向、判断标准和行业来源无需固化在第三方 SaaS 产品中。
3. **具备内网扩展基础**：在甲方授权和完成适配开发后，可接入内网搜索、内部文档库、历史报告和专业数据库，形成公开信息与内部信息的联合调研能力。
4. **可实施分级网络策略**：可按部署要求配置公网访问代理、域名白名单、本地搜索和本地模型，逐步提升隔离程度。
5. **为专属知识闭环提供数据基础**：本地保存的历史材料和报告可在后续扩展中用于专题更新、差异比较、事件时间线和长期监测。
6. **成本结构透明**：模型请求、搜索次数、抓取次数、下载字节和并发均有明确预算，不必完全依赖不可见的云端计费逻辑。
7. **便于验收与审计**：功能、错误码、数据格式和安全边界均有自动化测试，甲方可以在自己的环境中复现验收结果。
8. **便于二次开发**：本地 API、结构化 JSON 和 Markdown 产物可接入门户、知识库、档案系统和业务审批流程。

## 九、适用场景

本系统优先适用于：

- 行业、产业链和技术发展专题调研。
- 政策法规、标准规范和监管动态梳理。
- 企业、项目、产品、竞争对手和合作对象公开信息调查。
- 重大事件背景研究与持续信息补充。
- 投资、供应链和市场研究中的公开材料归集。
- 舆情事件的事实背景、来源分歧和时间线整理。
- 大量 PDF、Office、扫描件、访谈音视频混合存在的材料调查。

对于只需要简单问答、文案润色、通用办公助手或无需保存证据的一次性任务，通用云端智能体仍然可能更方便。本系统的优势会随着任务重要性、材料复杂度、审计要求和持续积累需求的提高而更加明显。

## 十、当前边界与部署前提

为保证甲方能够正确评估，当前版本存在以下明确边界：

1. **本地部署不等于默认完全离线**：Agent、工作台、任务状态、材料和报告均可本地部署，但默认模型配置使用外部 OpenAI 兼容 API。若要求任务内容和材料不发送给第三方模型服务，需要接入本地兼容模型及本地或内网检索；公开互联网采集仍需经过甲方批准和控制的网络出口。
2. **当前是单机工作区架构**：适合单部门试点和受控并发任务，尚未实现多租户、细粒度 RBAC、高可用集群和分布式任务队列。
3. **公开网页可访问性不可完全保证**：登录墙、验证码、反爬策略、动态渲染和站点故障可能导致材料无法获取；系统会保留失败状态并给出 1 星跳过建议，但不能绕过网站授权边界。
4. **多媒体处理依赖本地组件**：完整能力需要安装 Tesseract、FFmpeg、LibreOffice 和 faster-whisper；缺失时原件仍会保留，但不能作为文本证据使用。
5. **阅读推荐不是可信度评级**：星级是当前任务下的阅读价值，不能替代业务专家对来源权威性和结论影响的最终判断。
6. **系统辅助而不替代最终决策责任**：对高风险决策、法律意见、投资结论或对外发布材料，仍应由相应专业人员复核。

## 十一、后续扩展方向

### 第一阶段：生产化与治理

- 增加统一身份认证、角色权限、操作审计和敏感任务访问控制。
- 增加工作区加密、备份恢复、保留期限和成果归档策略。
- 提供本地模型、代理网关、域名白名单和隔离网络部署模板。
- 将当前运行状态与处理器健康状态接入运维监控。

### 第二阶段：持续情报与专题资产

- 增加定时任务、专题订阅、来源变化检测和增量更新报告。
- 建立来源目录、实体库、事件时间线和跨任务材料复用机制。
- 对同一主题的新旧报告进行差异分析，突出新增事实、撤回信息和口径变化。
- 建立面向不同部门的报告模板、审批流和发布流程。

### 第三阶段：多模态理解增强

- 对 PDF 和 Office 表格进行结构化提取，保留单元格级来源定位。
- 增加图片、图表和地图的语义理解，不仅依赖 OCR 文字。
- 优化长音视频分段、说话人识别、时间戳引用和关键片段定位。
- 建立跨文档实体对齐和数据口径识别，减少同名主体和统计口径混淆。

### 第四阶段：平台化扩展

- 在并发量和协作需求明确后，引入关系数据库、对象存储和持久化任务队列。
- 提供多用户协作、任务分派、人工复核、批注和版本管理。
- 对接甲方知识库、档案系统、数据中台和业务应用。
- 建立可量化的质量指标，包括核心问题回答率、引用可复核率、高价值材料比例、人工复核修改率和单份报告交付周期。

上述扩展应以真实使用数据为依据逐步实施，不建议在试点阶段一次性建设复杂平台。

## 十二、建议的甲方验收指标

为了客观评价系统价值，建议试点期使用以下指标，而不是只评价语言表达效果：

| 指标 | 建议验收方式 |
| --- | --- |
| 核心问题覆盖 | 检查报告是否逐项回答用户问题，并明确标记信息缺口 |
| 引用可复核率 | 随机抽取结论，确认可定位到归档原文和精确引文 |
| 材料处理能力 | 使用网页、PDF、Office、图片、音频和视频混合样本验证 |
| 来源多样性 | 检查是否覆盖一手来源、政府、专业媒体和必要的交叉来源 |
| 冲突处理 | 提供相互矛盾的材料，确认系统不会静默合并结论 |
| 报告完整性 | 修改报告或引用正文后，确认任务完成门禁能够拒绝 |
| 阅读效率 | 由业务人员验证星级与简评是否减少筛选原文时间 |
| 中断恢复 | 在深度采集中取消并恢复，检查队列和已采集状态是否保留 |
| 数据归属 | 确认任务、材料、证据和报告均按部署策略落在甲方环境 |
| 运行成本 | 统计单任务模型请求、搜索、抓取、下载量和人工复核时间 |

## 十三、结论

本地情报调研智能体的特殊价值，可以概括为“一个专用流程、两类成果、三层保障”：

- **一个专用流程**：围绕公开信息调研，从主题规划一直推进到正式报告交付。
- **两类成果**：面向管理层的结构化报告，以及面向业务人员的材料导读和原始资料库。
- **三层保障**：安全采集保障、证据与语义审核保障、报告及引用完整性保障。

通用云端智能体擅长快速提供广泛能力，但其标准化产品形态通常难以同时满足甲方对本地资产沉淀、证据审计、复杂材料处理、流程固化和持续定制的要求。本系统把这些要求作为核心架构，而不是附加功能。

建议以若干真实专题开展本地试点，对报告交付周期、引用可复核率、材料筛选效率和人工修改量进行量化比较。在试点证明价值后，再逐步建设权限治理、持续监测、内部知识接入和平台化协作能力。这样既能尽快形成可用成果，也能确保后续投入直接服务于甲方的实际情报工作。
