# Documentation

Project documentation is intentionally limited to four categories.

| Need | Start here |
| --- | --- |
| Run the current system or locate modules | [Project README](../README.md) |
| Understand current domain terms | [Domain context](../CONTEXT.md) |
| Plan the next iteration | [Outstanding work](../TODO.md) and [business requirements](../specs/002-monitor-factcheck-media/spec.md) |
| Deploy dynamic-page collection | [Dynamic-page deployment](development/js-dynamic-page-deployment.md) |
| Review dated capability or evaluation findings | [Reports](reports/) and [experiment records](../experiments/README.md) |
| Consult previous designs or briefings | [Architecture documents](architecture/) and [presentations](presentations/) |

Directory meanings and maintenance rules are defined in [AGENTS.md](AGENTS.md).

Several architecture documents, development plans, and decks predate the
engine refactor and still describe removed modules. They are historical design
material pending review, not current implementation or deployment instructions.
Use the README, domain context, source, and tests for current behavior; do not
interpret old test counts or unchecked planning lists as today's status.
