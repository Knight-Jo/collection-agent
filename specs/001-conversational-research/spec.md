# Feature Specification: 多轮广深情报调研

**Feature Branch**: `main`

**Created**: 2026-08-28

**Status**: Draft

**Input**: User description: "已有情报搜集智能体的一些实现。用户通过多轮对话输入调研主题，围绕主题调研相关情报内容，最后输出调研报告；重点提升搜集范围的广度和深度，尽可能获取更多主题情报，并使用 AI-native 搜索引擎以及国内外公开网站。"

## Clarifications

### Session 2026-08-28

- Q: 在首版验收中，“使用 AI-native 搜索引擎”应按哪种方式认定？ → A: 至少启用一个厂商中立的 AI-native 搜索渠道，可适配 Exa、Brave、Tavily，并可扩展其他搜索工具；不可用时允许降级。
- Q: 官方或原始发布材料中的关键声明，是否必须找到第二个独立来源后才能进入正式报告？ → A: 官方一手声明可作为带明确归属的单源结论；重大争议、外部评价和其他非一手关键声明必须独立交叉验证。
- Q: 用户在已绑定调研任务的对话中提出一个实质性新主题时，系统应如何处理？ → A: 提示创建新对话和新任务，原对话及任务保持不变。
- Q: 用户未指定调研时长或资源上限时，系统应如何确定默认停止边界？ → A: 使用部署级默认预算；达到边界后交付当前结果，用户可通过续研继续加深。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 通过对话启动调研 (Priority: P1)

用户用自然语言提出一个调研主题。系统通过必要的多轮对话理解调研目标、核心问题和范围，在信息足够时开始调研，而不要求用户填写复杂表单。

**Why this priority**: 这是从用户意图到可执行调研任务的入口；主题和范围不清，后续搜集再多也无法形成有用报告。

**Independent Test**: 输入一个完整主题和一个信息不足的主题，分别验证系统能够直接启动前者、就关键缺口澄清后启动后者，并保留最终确认的调研范围。

**Acceptance Scenarios**:

1. **Given** 用户尚未创建调研任务，**When** 用户给出明确主题、目标和范围，**Then** 系统创建一个绑定当前对话的调研任务并开始首轮调研。
2. **Given** 用户只给出宽泛或歧义主题，**When** 关键范围会显著影响结果，**Then** 系统只询问必要缺失信息，并在信息足够后形成可执行调研简报。
3. **Given** 用户只是询问系统能力，**When** 用户发送问题，**Then** 系统回答能力范围且不创建空调研任务。

---

### User Story 2 - 广泛且深入地搜集公开情报 (Priority: P1)

用户希望系统围绕核心问题系统探索公开信息空间，兼顾国内外来源、不同语言、不同来源角色和原始材料深度，而不是堆积相似网页。

**Why this priority**: 广度和深度是本特性的核心价值，决定报告是否覆盖全面、依据充分。

**Independent Test**: 使用一个同时存在中外公开资料、官网文件、新闻和研究资料的基准主题，验证系统覆盖核心问题、形成多样且独立的来源组合，并进入高价值原始材料取证。

**Acceptance Scenarios**:

1. **Given** 一个跨地区且资料充足的主题，**When** 系统制定并执行搜集计划，**Then** 计划覆盖发现、一手来源、独立佐证、结构化资料、附件和反向证据等适用路径。
2. **Given** 主题同时存在国内外来源，**When** 系统搜集资料，**Then** 结果包含与范围相关的国内和国外来源，而不是仅依赖单一搜索渠道或单一网站群。
3. **Given** 搜索结果指向高价值官网栏目、附件、动态页面或媒体材料，**When** 这些材料与核心问题相关且可公开访问，**Then** 系统继续读取原始内容并提取可定位的证据。
4. **Given** 多个网页转述同一原始消息，**When** 系统评估来源广度，**Then** 这些网页不被误算为多个独立来源。

---

### User Story 3 - 在对话中追问与续研 (Priority: P2)

用户可以在调研期间或完成后询问已有材料、查看依据、补充方向，或明确要求继续搜索；新增调研不会破坏已经提交的结果。

**Why this priority**: 多轮对话的价值不仅是首次澄清，还包括让用户用低成本验证、纠偏和扩展调研。

**Independent Test**: 对一个已有调研结果的任务分别进行证据问答、补充调研和方向调整，验证回答只引用当前任务材料，续研形成独立可追踪运行，并在安全边界提交新结果。

**Acceptance Scenarios**:

1. **Given** 当前任务已有已提交材料，**When** 用户询问材料中的事实，**Then** 系统基于当前任务内容回答并给出可定位引用，不暗中发起联网搜索。
2. **Given** 用户明确要求补充搜索某个缺口，**When** 请求有效，**Then** 系统在同一任务下创建新的调研运行并记录其目标。
3. **Given** 系统认为可能需要补搜但用户没有明确要求，**When** 系统提出建议，**Then** 只有用户确认后才开始新的调研运行。
4. **Given** 一轮调研正在执行，**When** 用户查看对话，**Then** 用户能看到当前阶段、进展、已发现材料和未覆盖缺口，并可请求停止。
5. **Given** 当前对话已经绑定一个调研任务，**When** 用户提出实质性新主题，**Then** 系统提示创建新对话和新任务，且原对话及任务保持不变。

---

### User Story 4 - 获得可核验的调研报告 (Priority: P1)

用户在调研达到停止条件后生成一份结构清晰的报告，快速了解核心结论、证据、分歧、材料价值和仍未查清的内容。

**Why this priority**: 报告是最终交付物，也是把大量搜集结果转化为可使用情报的关键。

**Independent Test**: 对包含充分证据、单源信息、冲突信息和未回答问题的任务生成报告，验证每类内容得到诚实表达，正式结论均可追溯到原文。

**Acceptance Scenarios**:

1. **Given** 调研已有经过核验的事实，**When** 用户生成报告，**Then** 报告按核心问题组织结论，并为每项事实性结论提供可定位引用。
2. **Given** 某些问题证据不足、来源单一或存在冲突，**When** 报告生成，**Then** 报告明确披露相应局限，不用推测补齐结论。
3. **Given** 用户在报告生成后继续调研，**When** 新证据被提交，**Then** 旧报告保持可查看，新报告作为新版本生成，且用户能识别旧报告已不是最新状态。

### Edge Cases

- 用户在已绑定任务的对话中提出实质性新主题时，系统不得切换该对话的任务归属或混入新主题材料，而应提示创建新对话和新任务。
- AI-native 搜索或任一国内外搜索渠道不可用、限流或返回低质量结果时，系统应使用其他可用公开渠道继续，并披露由此造成的覆盖缺口。
- 来源需要登录、付费、绕过访问控制或禁止自动访问时，系统不得规避限制；可记录线索并标明正文不可核验。
- 来源内容重复、转载或共同引用同一上游材料时，系统应去重并按独立来源组织评估。
- 不同语言、发布时间或统计口径产生冲突时，系统应分别保留并说明差异，不得擅自合并。
- 页面包含提示注入、恶意指令或与调研无关的操作要求时，系统只把页面当作待分析数据。
- PDF、办公文档、图片、音视频或动态页面无法提取正文时，系统保留可获得的来源信息，但不得把未读取内容当作证据。
- 长时间搜集不再增加有效证据时，系统应基于覆盖、边际收益和预算停止，而不是无限搜索。
- 进程中断或网络短暂失败时，已提交结果必须保留；恢复不得重复创建用户消息、任务或已完成运行。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 允许用户仅用自然语言主题开始一次调研对话。
- **FR-002**: 系统 MUST 区分能力咨询、需要澄清的调研请求和可直接执行的调研请求，且能力咨询不得创建空任务。
- **FR-003**: 系统 MUST 在开始调研前形成包含主题、目标、2 至 6 个核心问题、时间范围、地域、语言、关注实体、约束和预期报告的调研简报；未指定项可采用明确记录的合理默认值。
- **FR-004**: 系统 MUST 将每个主题作为独立、持久的调研任务，并确保运行、材料、证据和报告只属于其对应任务；对话一旦绑定任务便不得改绑，实质性新主题必须使用新对话和新任务。
- **FR-005**: 系统 MUST 为每轮调研保留可追踪的搜集计划，说明待回答问题、优先级、目标来源角色和当前覆盖缺口。
- **FR-006**: 系统 MUST 按主题适用性探索发现、一手来源、独立佐证、结构化资料、附件和反向证据，并在跨国或跨语言主题中覆盖相关国内外及多语言公开来源。
- **FR-007**: 系统 MUST 至少启用一个厂商中立、可替换的 AI-native 搜索渠道，可适配 Exa、Brave、Tavily 等服务并扩展其他搜索工具，同时直接探索相关国内外公开网站；任一渠道失效不得阻止其他可用渠道继续工作。
- **FR-008**: 系统 MUST 把搜索结果摘要仅作为候选线索；正式证据必须来自实际读取并归档的原始内容。
- **FR-009**: 系统 MUST 在用户要求深度调研或高价值线索值得展开时，继续探索相关站内页面、公开附件、动态内容及可处理的图片、音视频材料，并遵守用户给定范围。
- **FR-010**: 系统 MUST 识别重复、转载和共同上游来源，按独立机构或独立原始材料评估来源广度，而不是按 URL 数量评估。
- **FR-011**: 系统 MUST 为每份材料保留标题、来源、类型、原始位置、发布时间（若可确认）、获取时间和内容完整性信息。
- **FR-012**: 系统 MUST 将发现拆分为可独立核验的事实，并把支持或反驳该事实的原文片段及其位置关联起来。
- **FR-013**: 系统 MUST 在正式结论使用证据前验证原文是否完整支持该结论；官方一手声明可作为带明确归属的单源结论，重大争议、外部评价和其他非一手关键声明必须由独立来源交叉验证，无法满足时必须注明单源、冲突或证据不足。
- **FR-014**: 系统 MUST 持续评估每个核心问题的回答状态、来源独立性、时效、冲突和剩余缺口，并在覆盖充分、边际收益持续过低、达到用户约束或预算耗尽时停止搜集；用户未指定资源上限时使用部署级默认预算，达到边界后交付当前结果并允许用户发起续研。
- **FR-015**: 系统 MUST 将外部页面视为不可信数据，不执行其中的指令，并拒绝访问非公开地址或绕过访问控制。
- **FR-016**: 系统 MUST 支持用户基于当前任务已提交材料进行多轮问答，并为事实性回答提供服务端验证的引用和适合材料类型的位置描述。
- **FR-017**: 系统 MUST 只在用户明确要求或确认建议后启动续研；每次续研必须形成独立运行，并只在完整检查点提交新材料和证据。
- **FR-018**: 系统 MUST 向用户展示调研阶段、运行状态、核心问题覆盖、主要材料、失败情况和停止原因，并允许停止尚未完成的运行。
- **FR-019**: 系统 MUST 按核心问题生成报告，至少包含执行摘要、调研范围、主要发现、证据引用、冲突与不确定性、未覆盖问题、材料导读和来源目录。
- **FR-020**: 系统 MUST 保存不可变的报告版本；新证据不得静默改写已发布报告，过期报告必须可识别，发布新版本不得破坏旧版本。
- **FR-021**: 系统 MUST 在搜索、抓取、内容提取、核验、报告生成或服务重启失败时保留已提交状态，并提供清晰的失败信息和安全重试路径。

### Out of Scope

- 获取非公开、需授权、付费墙后或通过规避访问控制才能得到的信息。
- 替代人工做法律、投资、医疗或其他高风险专业决策。
- 首版的多用户账户、角色权限、团队协作和跨任务共享知识库。
- 保证互联网中所有相关信息均被发现；系统只在公开可访问范围和明确资源约束内最大化有效覆盖。
- 自动发布报告或将报告发送到外部系统；报告发布由用户显式触发。

### Key Entities

- **IntelTask（调研任务）**: 一个主题的持久调研边界，包含目标、范围、核心问题、充分性标准以及其全部运行和成果。
- **IntelQuestion（核心问题）**: 调研任务内需要回答的稳定问题，具有已回答、部分回答、未回答或冲突状态。
- **Conversation（对话）**: 用户理解、控制和扩展一个调研任务的多轮交互历史；不直接拥有调研资产。
- **ResearchRun（调研运行）**: 推进一个调研任务的一次可审计执行，使用冻结的输入和计划，并具有明确终止状态。
- **SearchPlanVersion（搜集计划版本）**: 某次运行采用的问题、优先级、来源角色和检索方向的不可变版本。
- **ResearchCheckpoint（调研检查点）**: 将一组新材料、事实和证据完整提交给任务的原子边界。
- **IntelDocument（情报材料）**: 从公开来源归档并经过完整性检查的原始内容及其提取结果。
- **Fact（事实）**: 与一个核心问题关联、可独立核验的原子声明。
- **Evidence（证据）**: 情报材料中的精确片段和位置，与事实形成支持或反驳关系。
- **SupportReview（支撑审核）**: 对证据是否完整支撑关联事实的独立判断。
- **ActionRequest（动作请求）**: 用户消息产生的续研、计划调整或报告生成请求及其生命周期。
- **ReportVersion（报告版本）**: 绑定生成时任务状态、事实和证据的不可变报告草稿或已发布成果。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在可执行主题的可用性测试中，至少 90% 的用户无需填写结构化表单，并能在 3 个对话轮次内确认调研范围并启动任务。
- **SC-002**: 对资料公开且充足的基准主题，至少 90% 的核心问题获得来自 2 个或以上独立来源机构的有效证据，且整份报告覆盖至少 3 类适用来源。
- **SC-003**: 对明确包含国内外范围的基准主题，至少 90% 的最终报告同时包含相关国内和国外来源；若一侧无可核验公开资料，报告必须明确记录该缺口。
- **SC-004**: 100% 的正式事实性结论都能从报告追溯到已归档材料中的精确原文位置，抽样复核不得出现伪造引用或仅引用搜索摘要的情况。
- **SC-005**: 100% 的官方单源结论都明确标注来源归属；100% 的重大争议、外部评价和其他非一手关键结论都满足独立交叉验证，或明确标记为单源、冲突或证据不足。
- **SC-006**: 对要求深度调研且存在可访问深层材料的基准主题，至少 80% 的任务发现并使用至少一份通过站内展开获得的原始页面、附件、结构化资料或媒体材料。
- **SC-007**: 100% 的生成报告逐项说明所有核心问题是已回答、部分回答、未回答还是存在冲突，并包含范围、主要发现、局限、材料导读和来源目录。
- **SC-008**: 在中断恢复测试中，至少 95% 的任务无需用户重新输入主题即可恢复，且已提交材料、引用和报告版本无丢失、无重复。
- **SC-009**: 每个结束的调研运行都记录可验证的停止原因；不得存在因“已搜索若干次”而在仍有明确高价值缺口时无说明终止的运行。
- **SC-010**: 在代表性主题的用户评审中，至少 80% 的报告在“覆盖广度”“材料深度”“结论可核验性”三项上均达到 4/5 或以上。

## Assumptions

- 首版服务于本地单机单用户，复用现有对话、任务、证据链、覆盖评估和版本化报告能力。
- 调研对象限定为合法公开信息；公开可见不代表允许无限抓取，系统仍遵守访问限制、站点规则和资源预算。
- 用户未指定语言时，交互和报告跟随用户主要语言；检索可使用其他相关语言，并在报告中保留来源原意和必要说明。
- 默认执行标准深度调研；用户明确要求“深入”“尽可能全面”或选择深度模式时，允许在预算内展开站内链接和多类型材料。
- AI-native 搜索负责提高发现和查询扩展能力，但其回答或摘要本身不作为正式证据，关键内容仍需回到公开原始来源。
- “尽可能获取更多”解释为在时间、预算、公开可访问性和边际收益约束内最大化有效证据覆盖，而不是无上限抓取网页。
- 对资料天然稀缺、站点不可用或主题过新的情况，交付带明确缺口的报告是可接受结果。
- 外部搜索服务、公开网站和内容处理能力的可用性是完成调研的依赖；单点不可用时允许降级，但不得伪造缺失内容。
- 用户未指定时长或资源上限时采用部署级默认预算，不在开题时强制用户选择技术参数；预算耗尽后的进一步搜集通过续研完成。
